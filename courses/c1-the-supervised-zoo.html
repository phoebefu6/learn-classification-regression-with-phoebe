Part 0

One question, seven ways of answering it

Every algorithm in this course answers the same two Lumen questions - will this session convert, and how big will the order be - but each answers in its own voice. A linear model draws a straight line. A tree asks yes/no questions. kNN just looks at the neighbors. Naive Bayes multiplies probabilities. An SVM hunts for the widest gap. None of them is "the best one"; each is a different bet about what shape the truth has. Learning the zoo means learning which bet fits which data - that judgement is what separates someone who calls .fit() from someone who models.

Part 1 · the map

Seven algorithms, two families 8 min live

The zoo looks big until you see the family resemblance. Model-based algorithms compress the training data into a small set of learned numbers - weights, split rules, class statistics - then throw the data away. Instance-based algorithms keep the data and answer by looking things up. That one distinction predicts most of each algorithm's personality: training speed, prediction speed, memory, and how the boundary looks.

LiveParametric vs non-parametric - the vocabulary that unlocks the docs4 min▶

Parametric models have a fixed number of learned parameters no matter how much data you feed them. Linear regression on 7 features learns 8 numbers whether you train on 400 rows or 40 million. That makes them fast, small, and stable - and caps how bendy they can get.

Non-parametric models grow with the data. kNN's "model" is the whole training set; a tree can keep splitting as long as rows remain. They can fit almost any shape - which is power and danger in one feature: the bendier the family, the easier it memorizes noise.

scikit-learn's user guide calls kNN "non-generalizing" for exactly this reason: it does not compress the data into a generalization, it remembers. You will feel the consequence in the live tool below - and measure it properly in session 5.

Real worldA fraud team asked why their kNN scorer needed 40 GB of RAM in production while the logistic model next to it needed kilobytes. Answer: kNN ships the training data as the model. Parametric vs non-parametric is not textbook trivia - it is your memory bill.

Part 2 · the one picture

The decision boundary - where a model changes its mind 10 min live

Take any classifier, feed it every point on a 2D map, and paint each point by the predicted class. The seam between the colors is the decision boundary - the set of places where the model flips from "no" to "yes". Every classifier in the zoo draws this seam in its own signature style: logistic regression draws one straight line, trees carve axis-parallel rectangles, kNN traces the local crowd, RBF kernels wrap curves around clusters. Learn to read this picture and you can identify an algorithm from its boundary like a naturalist reading footprints.

LivePlay: the boundary explorer6 min▶

These are real models fit live in your browser - real gradient descent, real CART splits, real neighbor votes. Two datasets: Lumen real is 300 actual generator points (150 converters, 150 non-converters, spend x pages standardized), and Lab: two moons is a stylized shape for geometry intuition - clearly not Lumen data. Try this script:

  • Start on Lab + kNN. Drag k down to 1: train accuracy hits ~100% while test accuracy sinks. That gap IS overfitting - you will see it on every algorithm all course.
  • Switch to tree and crank depth: watch it carve one rectangle per stray point.
  • Switch to Lumen real: every algorithm gets humbler. Two features of real checkout data hold a weak, honest signal (~60% accuracy on a balanced sample) - real data whispers, it does not shout.
Keep this tool in mind: sessions 3, 5, 7 and 8 each come back to it with their own algorithm and knob. By session 9 you will predict the boundary shape before you select it.
Self-studyWhy only two features in the picture?4 min▶

Real Lumen models use all seven features; boundaries live in 7-dimensional space and cannot be drawn. Two features are a teaching window, not a recommendation - and the window has a catch: with fewer features, the models above score lower than the ~0.69 ROC-AUC you will get with the full feature set in session 3.

The shapes, however, generalize perfectly: a logistic model in 7D draws a flat 6-dimensional plane exactly as it draws a line in 2D; a tree still cuts one feature at a time; kNN still votes among neighbors. Learn the geometry in 2D, trust it in 7D.

Build-along

Rebuild Lumen, then meet your baselines ★ 18 min · everyone builds

Two jobs: regenerate the exact Lumen dataset (seed 42 - if you still have lumen_sessions.parquet from intro-ml, this run will produce the identical file), then fit one representative from three families with identical code and stand up the leaderboard this course exists to explain.

Recreate the dataset. Run the generator exactly as intro-ml b1 shipped it - same seed, same coefficients. Sanity-check the fingerprint: 40,000 rows, ~3% conversion, AOV mean ~$73.

Build the shared preprocessing. One ColumnTransformer: one-hot the four categoricals, scale the three numerics. Fit on train only - the b2 discipline, forever.

Fit three animals with one loop. Same Pipeline, three estimators swapped in - the estimator API is why this is three lines, not three scripts.

Read the leaderboard. ROC-AUC on the held-out test set. Do not explain the ranking yet - explaining it is the whole course.

baselines.py - the leaderboard we will spend nine sessions understandingimport pandas as pd from sklearn.model_selection import train_test_split from sklearn.compose import ColumnTransformer from sklearn.preprocessing import OneHotEncoder, StandardScaler from sklearn.pipeline import Pipeline from sklearn.linear_model import LogisticRegression from sklearn.tree import DecisionTreeClassifier from sklearn.neighbors import KNeighborsClassifier from sklearn.metrics import roc_auc_score df = pd.read_parquet("lumen_sessions.parquet") cat = ["channel", "device", "new_vs_returning", "product_category"] num = ["pages_viewed", "session_hour", "prior_30d_spend"] X, y = df[cat + num], df["converted"] X_tr, X_te, y_tr, y_te = train_test_split( X, y, test_size=0.25, random_state=42, stratify=y) prep = ColumnTransformer([ ("cat", OneHotEncoder(handle_unknown="ignore"), cat), ("num", StandardScaler(), num)]) zoo = { "logistic": LogisticRegression(max_iter=2000), "tree d=5": DecisionTreeClassifier(max_depth=5, random_state=42), "kNN k=101": KNeighborsClassifier(n_neighbors=101)} for name, model in zoo.items(): pipe = Pipeline([("prep", prep), ("model", model)]).fit(X_tr, y_tr) proba = pipe.predict_proba(X_te)[:, 1] print(f"{name:10s} ROC-AUC {roc_auc_score(y_te, proba):.2f}") # logistic ROC-AUC 0.69 # tree d=5 ROC-AUC 0.66 # kNN k=101 ROC-AUC 0.64
If your numbers differ in the 2nd decimal: fine - tiny library-version jitter is normal. If they differ in the 1st decimal, check the seed (42 in the generator AND the split) and that the scaler sits inside the pipeline, not before the split.
Real worldNotice what just happened operationally: swapping algorithms was a one-line change inside a dict. Teams that structure experiments this way test seven models in the time others test one - the estimator API is a productivity feature disguised as a design choice.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · What is the decision boundary of a classifier?

Paint every point in feature space by predicted class; the seam where the color changes is the boundary. Its shape is the algorithm's signature: line, rectangles, local wobble, or smooth curves.

2 · kNN is called "instance-based" (or "non-generalizing") because...

kNN's model IS the training data. That buys flexibility (any boundary shape) and costs memory and prediction speed - the family trade-off in one algorithm. It handles regression fine (session 5).

3 · In the explorer, kNN with k=1 shows train accuracy ~100% and much lower test accuracy. What is that gap called and why does it appear?

At k=1 each training point predicts itself perfectly, so the boundary wraps around every noisy point. Perfect train score, poor test score - the overfitting tell you will re-meet on trees (depth), polynomials (degree), and RBF (gamma).
